# 블로그 포스팅 문장 검토

기술 블로그 포스팅의 문장, 표현, 가독성을 검토합니다.

## 인수 처리

사용자 입력: `$ARGUMENTS`

| 인수 | 동작 |
|------|------|
| (없음) | 최근 수정된 포스트 자동 탐색 |
| `파일경로` | 해당 파일 검토 |

## 검토 항목

### 1. 문장 구조

- 문장 길이가 적절한가 (너무 길면 분리)
- 주어-서술어 호응이 맞는가
- 불필요한 수동태가 있는가

### 2. 표현

- 어색하거나 부자연스러운 표현
- 불필요한 반복
- 모호한 지시어 (이것, 그것, 저것)

### 3. 톤 일관성

- 문어체/구어체 혼용 여부
- 존댓말/반말 일관성
- 전문성과 친근함의 균형

### 4. 기술 용어

- 용어 설명 없이 사용된 전문 용어
- 영어/한글 표기 일관성
- 약어 첫 사용 시 풀어쓰기

### 5. 가독성

- 문단 길이 적절성
- 접속어 남용 여부
- 리듬감 (문장 길이 변화)

## 실행 절차

### 1. 파일 읽기

```bash
# 인수가 없으면 최근 수정된 포스트 찾기
ls -t _posts/*.md | head -1

# 인수가 있으면 해당 파일
cat "$ARGUMENTS"
```

### 2. 문장 분석

파일을 읽고 위 검토 항목에 따라 분석합니다.

### 3. 결과 출력

개선이 필요한 부분을 diff 형식으로 제안:

```markdown
## 문장 검토 결과

### 발견된 이슈 (N건)

#### 1. (이슈 유형)

**위치**: (섹션/문단 위치)

**현재**:
> (현재 문장)

**제안**:
> (수정 제안)

**이유**: (수정 이유)

---

#### 2. (이슈 유형)
...

### 요약
- 수정 필요: N건
- 검토 필요: M건

### 적용 방법
위 제안을 검토 후 "전체 승인" 또는 개별 번호를 선택하세요.
```

## 수정 적용

사용자가 승인한 항목만 Edit 도구로 수정합니다.

| 응답 | 동작 |
|------|------|
| `전체 승인` | 모든 제안 적용 |
| `1, 3, 5` | 해당 번호만 적용 |
| `1 빼고` | 해당 번호 제외 적용 |
| `취소` | 수정하지 않음 |

## 블로그 스타일 가이드

이 블로그의 특징:
- **서술형 산문체** 사용
- 개인 경험 중심의 자연스러운 톤
- 기술적 정확성보다 맥락 전달 중시
- 글머리 기호 요약 대신 문장으로 서술
- 블로그 프로젝트에 `.claude/rules/blog-tone.md` 톤 규칙이 있으면 반드시 따른다

## 주의사항

- 의미 변경 없이 표현만 다듬기
- 저자의 개성이 담긴 표현은 존중
- 제안 시 이유를 명확히 설명
- 한 번에 너무 많은 수정 제안 X (5-10개 이내)

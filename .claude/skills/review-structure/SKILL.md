# 블로그 포스팅 구조 검토

기술 블로그 포스팅의 구조, 흐름, 시리즈 맥락을 검토합니다.

## 인수 처리

사용자 입력: `$ARGUMENTS`

| 인수 | 동작 |
|------|------|
| (없음) | 최근 수정된 포스트 자동 탐색 |
| `파일경로` | 해당 파일 검토 |

## 검토 항목

### 1. 기본 정보 확인

- **제목**: 명확하고 검색 친화적인가
- **태그/카테고리**: 적절한가
- **날짜**: 올바른가
- **시리즈 여부**: ref/series 필드 확인

### 2. 구조 분석

- **도입부**: 글의 목적과 배경이 명확한가
- **본문 흐름**: 논리적 순서로 전개되는가
- **섹션 구성**: 각 섹션이 적절한 깊이를 가지는가
- **마무리**: 요약 또는 다음 단계가 있는가

### 3. 시리즈 맥락 (해당 시)

시리즈물인 경우:
- 이전 글과의 연결 확인
- 다음 글 예고 여부
- 독립적으로 읽어도 이해 가능한가

### 4. 콘텐츠 유형 분류

| 유형 | 특징 |
|------|------|
| A. 기술 튜토리얼 | 단계별 가이드, 코드 예제 중심 |
| B. 프로젝트 회고 | 경험 공유, 의사결정 과정 |
| C. 개념 설명 | 이론/개념 중심 |
| D. 트러블슈팅 | 문제-원인-해결 구조 |

### 5. 콘텐츠 깊이 (5요소)

`.claude/rules/blog-content-criteria.md`의 5요소 중 **어떤 것이 핵심 주제로 다뤄지는지** 식별한다. 단순 후기성 글이 아닌 "기술 블로그" 글의 경우, 최소 1개가 명확히 드러나야 한다.

| 요소 | 점검 질문 |
|------|-----------|
| Why | 비즈니스/사용자 배경이 도입부에 드러나는가 |
| Trade-off | A/B 비교와 선택 근거가 본문에 있는가 |
| Architecture | 다른 스택/시스템과의 연결이 드러나는가 |
| How we solved | 단순 해결이 아닌 근본 원인 추적이 있는가 |
| AX | AI를 어떻게 녹여냈는지 구체적으로 다루는가 |

핵심 요소가 글의 **제목 / 도입부 / 결론**에서 드러나지 않으면, 어디서 보강할지 옵션을 제시한다.

## 실행 절차

### 1. 파일 읽기

```bash
# 인수가 없으면 최근 수정된 포스트 찾기
ls -t _posts/*.md | head -1

# 인수가 있으면 해당 파일
cat "$ARGUMENTS"
```

### 2. 분석 수행

파일을 읽고 위 검토 항목에 따라 분석합니다.

### 3. 결과 출력

```markdown
## 구조 검토 결과

### 기본 정보
- **제목**: (제목)
- **날짜**: (날짜)
- **태그**: (태그 목록)
- **시리즈**: (있음/없음)

### 구조 분석
- **콘텐츠 유형**: (A/B/C/D)
- **도입부**: (평가)
- **본문 흐름**: (평가)
- **마무리**: (평가)

### 개선 제안
1. (제안 1)
2. (제안 2)
...

### 다음 단계
구조 검토 완료 후 `/review-writing`으로 문장 검토를 진행하세요.
```

## 블로그 스타일 가이드

이 블로그의 특징:
- **서술형 산문체** 선호 (글머리 기호 요약 X)
- 개인 경험과 의사결정 과정 중시
- 기술적 깊이보다 맥락과 흐름 중시

검토 시 반드시 함께 참조하는 규칙 문서:
- `.claude/rules/blog-tone.md` — 문체/톤 규칙
- `.claude/rules/blog-content-criteria.md` — 5요소 콘텐츠 기준

## 주의사항

- 검토만 수행하고 직접 수정하지 않음
- 사용자에게 개선점을 제안하고 확인 후 수정
- 시리즈물인 경우 이전 글도 참조

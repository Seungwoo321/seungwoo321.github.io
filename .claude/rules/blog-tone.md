# 블로그 글 톤 규칙

이 블로그의 글을 작성하거나 검토할 때 반드시 지켜야 하는 톤 규칙.

## 과장 금지

- 저자가 직접 만들지 않은 것을 자기 것처럼 포장하지 않는다
- "자체 방법론을 만들어서", "빠진 조각을 찾았다", "통찰을 얻었다" 같은 드라마틱한 서사 X
- 사실을 담백하게 전달한다

## 출처와 겸손

- 남이 만든 방법론/도구를 가져다 쓴 것은 솔직하게 밝힌다
- "가져다 써보고 있다", "조합해서 쓰고 있다" 정도의 표현이 적절
- 저자를 실제보다 대단하게 보이게 만드는 표현은 모두 제거

## 경험과 선택 과정

- `content/pages/about.md`에 맞춰 문제를 만나고 시도하고 실패하고 다시 선택한 흐름을 보존한다
- 선택 이유와 예상 밖 결과를 이해하는 데 필요한 경험은 충분히 쓴다
- 구현 세부는 GitHub 링크로 보완하되 경험 자체를 링크로 대체하지 않는다
- 체감은 저자의 경험으로 표현하고 객관적인 성능·정책 사실과 구분한다
- 내가 내 입으로 자랑하는 느낌이 나면 안 된다

## 서술형 산문체

- 글머리 기호 나열보다 문장으로 풀어서 서술
- 개인 경험과 의사결정 과정 중시
- 기술적 깊이보다 맥락과 흐름 중시
- 소제목은 기존 글처럼 짧은 주제·명사구를 중심으로 쓴다. 본문 첫 문장을 서술형 제목으로 반복하지 않는다

## 조사 과정은 본문 밖에

- 사실 확인은 근거 장부에서 수행하고, 독자에게 필요한 출처는 짧은 링크나 각주로 붙인다
- “자료를 찾아보니”, “기억은 당시 안내와 맞는다”처럼 글을 검증한 과정을 경험담에 끼우지 않는다
- 연대기에 필요한 시간 표현만 남기고, 회상하고 있다는 설명이나 불확실성 단서를 문단마다 반복하지 않는다
- 불확실성이 중요한 주장에는 필요한 한정을 남긴다. 논지에 불필요한 날짜·모델명은 확인 과정을 늘어놓는 대신 생략한다
- 같은 판단이나 미완성 상태를 여러 절에서 다시 해설하지 않는다

## 마무리

- 경험을 통해 현재 어떤 선택을 했는지와 아직 판단하기 어려운 점을 담는다
- 독자에게 질문하거나 참여를 권하는 문장은 글의 맥락에 필요할 때만 쓴다
